# Transit route optimizer: dataset, graph and validation (step 1)

A* vs Dijkstra on a **synthetic, fictional** public transport network. This step contains
only the data, the graph definition and the checks. The algorithms and UI come next.

> All data here is generated by `generate_city.py`. It describes no real place or operator.

## Files

| File | Purpose |
|---|---|
| `network.py` | Data model, CSV read/write, the **state-expanded graph** (`TransitGraph.neighbors`) and the **heuristic**. One source of truth for every edge cost, so A* and Dijkstra can never disagree on costs. |
| `generate_city.py` | Seeded generator: `python generate_city.py --seed 42 --stops 80 --out data/synthetic_city` |
| `build_test_cases.py` | Writes 7 tiny hand-derived networks (16 queries) to `data/tests/` |
| `validate.py` | Dataset + heuristic validation (`--negative-control` proves the check can fail) |
| `check_tests.py` | Confirms every hand answer with two independent methods |
| `oracle.py` | Reference solvers for validation only (not your A*/Dijkstra) |
| `plot_city.py` | Interactive map: `python plot_city.py` writes `city_map.html` |
| `astar.py` | `search()`: A* and Dijkstra as one function (Dijkstra = heuristic off), `time_search()` |
| `journey.py` | Splits a found route into ride / wait / walk / penalty and into legs; asserts parts sum to the cost |
| `experiments.py` | All experiments; writes CSVs to `results/` (`--quick` for a smoke test) |
| `results/` | Experiment output the website will read (see below) |

Run order: `python generate_city.py` → `python build_test_cases.py` → `python validate.py --negative-control` → `python check_tests.py`.

## Cost model

```
cost = ride + wait + walk + penalty * transfers
wait = 0.5 * headway   (each boarding)
transfers = number of boardings - 1      (first boarding is free)
```

Defaults (in `config.json`): penalty 5 min, walking 4.8 km/h with 1.2 detour, access radius 0.6 km,
direct-walk cap 1.5 km, `v_max` 40 km/h.

## Graph

Nodes: `("R", route, i)` on a vehicle that just arrived at stop position `i`; `("A", stop)` standing at a stop
after alighting; `("O",)` origin point; `("D",)` destination point.

| Edge | Cost |
|---|---|
| ride | segment ride time |
| alight | 0 |
| walk (A→A) | link walk time |
| board (A→R) | headway/2 + penalty + first segment ride time |
| access (O→R) | walk to stop + headway/2 + first segment ride time (**no penalty**) |
| egress (A→D) | walk to destination |
| direct (O→D) | walk, only if within the cap |

A board edge includes the first ride segment, so a passenger cannot board and alight at the same stop.
That phantom leg was a real bug found by the validator (see below).

## Heuristic

`h(n) = euclidean(n, destination) / v_max`. Admissible and consistent because no edge exceeds `v_max` and
waits/penalties are non-negative. Verified on every edge and every node, not assumed.

## Reviewing the CSVs (checklist)

1. `stops.csv`: spot-check a few coordinates against `city_map.html`.
2. `routes.csv`: every route has an `_out` and `_in` row; metro headways (4-6) are shorter than bus headways.
3. `route_stops.csv`: `ride_min_from_prev` is 0 at seq 0 (non-loop); loop routes keep the closing segment time there.
4. `walk_links.csv`: `walk_min` is roughly `distance_km * 15`.
5. Hand-verify one case from `data/tests/*.json`; each query has its arithmetic in `derivation`.

## Experiments (`python experiments.py`, about 30 s)

Cities: seed 42 at 80 / 303 / 1003 stops. Query sets: fixed random stop pairs (300 / 300 / 200),
split into short / medium / long trips by straight-line distance terciles. Default penalty 5 min.
The run aborts if A* and Dijkstra ever disagree on cost, if a breakdown fails to sum to its cost,
or if a verified flip point is not confirmed by A*.

| File | Content |
|---|---|
| `queries.csv` | one row per trip and algorithm: cost, transfers, breakdown, expanded, generated, time |
| `summary_algorithms.csv`, `summary_comparison.csv` | per network and distance bucket: medians, p90, A*/Dijkstra ratios |
| `penalty_sweep_summary.csv`, `penalty_sweep_pairs.csv` | penalties 0..30: cost, transfers, breakdown, route changes |
| `penalty_flips.csv` | every 80-stop trip whose best route changes to fewer transfers, with the exact flip penalty |
| `baseline_queries.csv`, `baseline_summary.csv` | shortest-distance route evaluated under the real cost model |
| `networks.csv`, `experiment_meta.json` | sizes, seeds, checksums, definitions, timing method |

Deterministic columns (cost, transfers, expanded, generated, breakdown) are identical for identical
seeds; `time_us` varies by machine and run (about 10% between two runs here), so compare ratios.

Headline results (median per trip):

| Network | A* / Dijkstra expanded | A* / Dijkstra time | Heuristic tightness h/h* |
|---|---|---|---|
| 80 stops | 0.76 | 1.15 (A* slower) | 0.14 |
| 303 stops | 0.62 | 0.96 | 0.18 |
| 1003 stops | 0.54 | 0.79 (A* faster) | 0.27 |

A* never changed a cost (0 mismatches in 800 trips). Its advantage grows with network size because the
heuristic gets tighter; on small networks the cost of computing h outweighs the states it saves.

## Known limits

- Frequency-based model: no timetables, expected values only.
- Heuristic is loose (see results): `h/h*` is about 0.15 on the 80-stop city.
- Some corners of the city have no service, an artifact of the corridor-based generator.

# Step 4: the website (FastAPI + custom frontend)

## Run it

```bash
pip install -r requirements.txt
python server.py --open          # http://127.0.0.1:8000
```

The experiment CSVs in `results/` are already included. To regenerate them (about 30 s): `python experiments.py`.
Tests: `python check_tests.py`, `python validate.py --negative-control`, `python -m pytest test_backend.py -q`.

## Structure

```
server.py     FastAPI: checks the request, calls service.py, returns JSON. No routing logic.
service.py    Builds the JSON: city payload, plan (runs the real search), sweep, experiment tables from results/*.csv
astar.py      search(): A* and Dijkstra as one function        <- source of truth
journey.py    ride / wait / walk / penalty breakdown and legs  <- source of truth
network.py    graph, edge costs, heuristic                     <- source of truth
web/
  index.html      page shell (planner, experiments, how-it-works views)
  js/main.js      hash router, start-up
  js/api.js       the only place the browser calls the backend
  js/planner.js   sidebar, journey result, comparison, penalty sweep, search replay
  js/map.js       hand-built SVG map: pan/zoom, lines, stops, route, replay
  js/experiments.js  dashboard; every chart is drawn from /api/experiments
  js/about.js     "How it works" text (numbers read from the city config)
  vendor/plotly.min.js, fonts/   bundled, so it works offline
```

Data flow: `browser -> server.py -> service.py -> astar.py / journey.py / network.py`. The browser never computes a
route. Charts on the experiments page come from `results/*.csv` through `/api/experiments`.

## API

| Endpoint | Returns |
|---|---|
| `GET /api/city` | stops, lines (with colours), walking links, cost settings |
| `GET /api/route?origin=&dest=&algo=astar\|dijkstra&penalty=&replay=0\|1` | route legs, cost breakdown, transfers, expanded states, time, A*-vs-Dijkstra comparison, optional search trace |
| `GET /api/sweep?origin=&dest=` | same trip at penalties 0..30 |
| `GET /api/flips` | trips whose route changes with the penalty (from `penalty_flips.csv`) |
| `GET /api/experiments` | all dashboard data |

`origin` / `dest` are stop ids (`S037`) or map points (`x,y` in km; you walk to a stop within 600 m).

## Viva talking points

- **One search function.** `search(h_weight=1)` is A*, `h_weight=0` is Dijkstra. Differences in expanded states come only from the heuristic.
- **Why the state graph.** Cost of leaving a stop depends on the line you arrived on (transfer penalty, wait), so nodes are "on line L at stop i", not plain stops.
- **Why A* stays optimal.** `h = straight-line km / 40 km/h` never exceeds the true remaining cost and is consistent; `validate.py` checks every edge and has a negative control.
- **Honest result.** A* always expands fewer states, but it is not always faster in wall-clock time on the smallest network (heuristic lookups cost time). The dashboard says so from the data.
- **Transfer penalty** is a planning weight, not real time; the breakdown shows it as its own part, and `penalty_flips.csv` lists trips where raising it changes the route.
- **Shortest-distance baseline** shows that fewest kilometres is not lowest cost once waiting and transfers count.
- **Limits.** Synthetic city, frequency-based timetables (wait = headway/2), timings depend on the machine, no dark mode.
